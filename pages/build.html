The tools behind PlayTinker

Want to build your own game, app or website? These are the four tools we use to make PlayTinker. You can use them too, ideally with a grown-up alongside you.

1

ChatGPT

Makes the pictures. Characters, backgrounds, icons and artwork for your game.

2

Claude

Helps build it. Plans features, writes and explains code, and helps find bugs.

3

GitHub

Stores the files. Keeps every version of your project safe, so you can go back in time.

4

Fly.io

Puts it online. Runs your website or game so anyone with the link can use it.

Step by step: from idea to online

  1. Write a short brief

    Before any AI: what is it, who is it for, what does the player do, how do you win? Half a page is plenty. This is your plan, and you're in charge of it.

  2. Create your images with ChatGPT

    Describe each picture clearly: subject, style, colours and what it's for. Ask for a plain or transparent background for characters, and keep the same description so characters stay consistent. Our mascot Pip and the artwork on this site started this way.

    Create a friendly teal robot character for a children's game.
Big round eyes, an orange utility belt, a small star antenna.
Cartoon style, bold outlines, full body, standing, plain white background.

    Never upload photos of real people. Don't ask for famous characters or logos that belong to someone else.

  3. Build it with Claude, one step at a time

    Give context, ask for one feature, set rules and ask for an explanation. Test each step before asking for the next. For bigger projects, Claude Code can work directly with your project files.

    I'm making a browser game in plain HTML, CSS and JavaScript.
A hedgehog runs along and logs come towards it.
Step 1 only: draw the hedgehog and make it jump when I press space,
only when it's on the ground. Explain each part of the code.

  4. Check it like a creator

    Use the Creator's Check: can you explain it, does it work, have you tested it on a phone and a laptop, and did you improve it after feedback?

  5. Save it to GitHub

    Create a repository (a project folder that remembers history). Each time something works, make a commit with a short message like "added jumping". If you break something, you can go back.

    git init
git add .
git commit -m "First playable version"
git remote add origin https://github.com/YOUR-NAME/my-game.git
git push -u origin main

  6. Put it online with Fly.io

    Fly.io runs your project on its servers so others can use it. You install its command-line tool, launch the app once, then deploy each new version.

    fly auth login     # sign in (adult account)
fly launch         # first time: creates the app and fly.toml
fly deploy         # every time you want to publish an update

    Fly.io may charge for usage. Check its pricing first and set spending limits. A simple static game can also be hosted on free options such as GitHub Pages.

  7. Share it responsibly

    Write short release notes, ask a grown-up before sharing a public link, and keep personal details out of your project.

How this website is built

This concept website uses exactly the stack above, so it doubles as a worked example.

PartToolWhat it does here
Artwork and PipChatGPTConcept images, mascot designs and game scenes

Source code and historyGitHubStores the project; a GitHub Action deploys each update automatically

Why images and code use different AIs

Each tool is good at different things. Using the right tool for each job is a skill in itself.

Why GitHub matters

Version history means mistakes aren't scary. Professional developers rely on it every day.

Why not just "generate"?

Because you'd learn nothing and couldn't fix it. Building step by step makes it yours.
